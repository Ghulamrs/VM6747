# cxx1i review — x86_64-windows against cl (Fable 5.1, 2026-09-17)

Reviewed: **cxx1i x86_64-windows against cl 19.x (VS 2022) on the Windows box, HEAD `3c1130a`, 108 single-file probes and 9 cross-linked pairs (36 link combinations)**. The box copy was `C:\cxx1\review-cxx1i\cxx1-msvc.exe`; cl was run as `cl /nologo /EHsc /std:c++14`, and again with `/permissive-` for the over-acceptance question. Every probe was compiled and run by both compilers in `C:\cxx1\review-probes\fable17\`; a cross-linked pair was compiled by each compiler and linked in all four callee/caller combinations against `libcmt`. Probe sources and both outputs are under the scratch directory `.../scratchpad/review/` (`probes/`, `win/out/`); the ones that show a defect are copied to `review-probes-2026-09-17/` named by their id, each with both outputs in its first lines. Compiler-Cpp (`cxx1.exe`, built from `6d7386a`, the sealed base named for this review) was run on the Mac only, for section D; that checkout moved to `98d5ea7` ("Version 1.3: the seven fixes and the terminate scope, brought from Compiler-Cppi") during the session, so section D describes the base, not the current tip. Nothing was committed; the two build worktrees were removed.

A refusal that names its feature and is recorded in `docs/EXCLUSIONS.md` or a `tests/cases/*.notarget` is not a defect; section B lists the ones met. Paths below are under `Compiler-Cppi/`.

**Silent wrong answers first: A1, A2, A3, A4, A5, A6 - all of them at the boundary with cl-compiled code or in layout, none visible to a program compiled entirely by cxx1i, which is why the suites are green.** A8 and A9 are library wrong answers visible to any program. Everything else is a refusal or an over-acceptance.

## C. Confirmed to agree with cl (measured)
